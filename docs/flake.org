#+title: Flake infrastructure
#+subtitle: flake.nix and modules/flake
#+options: toc:t

Documentation for the flake framework layer: how the flake is assembled, the
inputs it pins, and the [[file:../modules/flake/][modules/flake]] modules that give the repo its
build/test surface.

* flake.nix

Auto-generated by [[https://github.com/denful/flake-file][flake-file]]; do not edit by hand. Regenerate after changing
inputs with:

#+begin_src shell
  nix run .#write-flake
#+end_src

The flake delegates to =flake-parts= and imports every file under
[[file:../modules/][modules/]] via =import-tree=. The ~den.aspects~ definitions inside those
modules therefore drive the whole build.

* Inputs

Pinned third-party flakes. Most are declared here in =flake.nix=, but some
modules declare their own via ~flake-file.inputs.<name>~ (merged back on
regeneration):

* modules/flake

** defaults.nix

Den-wide defaults applied to every host:

- State version =26.05= for both NixOS and home-manager
- Default includes: ~settings~ aspect, ~hostname~ battery, bash user shell
- Default user class schema: ~homeManager~

** dendritic.nix

Brings in the =dendritic= flake modules from =flake-file= and =den=, and wires
~__findFile~ so [[../modules/lunix/system.nix][aspects can refer to each other by angle-bracket path]] (e.g.
~<settings>~). Declares a handful of core inputs (den, den-diagram,
flake-file, home-manager, devenv, disko).

** namespaces.nix

Registers den namespaces: ~lix~ (user-aspect tree) enabled, ~lig~ (global
secrets/hosts glue) disabled (i.e. its aspects are available but not auto-included).

** devshell.nix

The bootstrap devshell (~nix develop~) you drop into on a fresh NixOS
installer. Provides:

- =just=, =git=
- =disko= / =disko-install= (pinned from flake.lock, not installer channel)
- Formatting tools =disko= shells out to: =cryptsetup=, =btrfs-progs=,
  =dosfstools=, =gptfdisk=, =parted=, =util-linux=
- =nixos-install-tools= for installing to /mnt
- =age=, =openssh=, =agenix= for secrets

Its ~shellHook~ prints the full reinstall runbook (inspect disk, stash LUKS
passphrase, ~just disko-format~, ~just install~, ~just switch~).

** apps.nix

Standalone launchers built from the already-configured home-manager
environment (no full switch):

- ~nix run .#emacs~ — the emacs package built from the repo =emacs/= config
  (~doomacs~ kept as a compat alias)
- ~nix run .#nixcord~ — the nixcord Discord client
- ~nix run .#facter~ — regenerate the hardware report

** vm.nix

~nix run .#vm~ boots the igloo configuration in NixOS's built-in VM
(~system.build.vm~), sharing the host /nix/store via overlay. Adds the
~vm-autologin~ battery so you land at a shell without a password.

** qemu.nix

~nix build .#qemu~ produces a standalone qemu-kvm runner on a separate
qcow2 disk image — unlike =vm.nix=, this mimics real hardware/UEFI. Used for
rehearsing disk installs and validating the boot chain.

- Overrides: ~DISK~, ~MEMORY~, ~CPUS~, ~ISO~, ~SNAPSHOT~, ~EXTRA_QEMU_ARGS~
- Boots OVMF firmware directly; snapshot mode (default) keeps the disk pristine

** diagrams.nix

Builds Mermaid diagrams of den's aspect-resolution graph:

- ~nix build .#diag-igloo~ — host-level aspect resolution (~.mmd~ text file)
- ~nix build .#diag-fleet~ — fleet-wide Sankey

** nh.nix

Exposes every host/home as a flake package so =nh= (Nix helper) can build and
switch them by name.

** battery/custom-class.nix

Den battery that merges user ~config~/~default~ content into the standard
~homeManager~ and ~nixos~ classes, applying high-priority overrides (priority
75) on top of the defaults.

** battery/os-user.nix

Den battery defining the ~os-user~ policy: routes user-class content to the
host's ~users.users.<userName>~ and injects ~osConfig~ so user modules can
reference the parent NixOS config. Creates the ~users.users.<name>~ entry even
with empty user content (home-manager references it).
