* Overview

Personal emacs config. Standalone `~/.emacs.d` replacement, built by nix
(`emacsWithPackagesFromUsePackage` from =emacs-overlay=). **Based on Doom
Emacs**: presents as doom emacs — same look, same `<leader>` keybindings,
same module set — without doom's module system, straight.el, or doom core.
Everything doom-specific is either ported into this repo or approximated with a
vanilla equivalent. Doom's module tree is kept at =doom-modules/= (gitignored)
as the reference for ports.

Four layers:

| layer    | file                   | role                                                                 |
|----------+------------------------+----------------------------------------------------------------------|
| boot     | =init.el=, =early-init.el= | entry, package.el off, autoloads, globals                            |
| backend  | =lunaris.el=             | unified framework: `leaf` DSL + luna-compat + manifest + tree loader |
| manifest | =manifest.el=            | `(lunaris! ...)` enabled modules, doom!-style                        |
| modules  | =config/ + =framework/=      | your config (always) + doom-ported modules (manifest toggle)                            |

* Boot — init.el

Flow:

1. =lunatix-emacs-dir= ← directory of =init.el= (works from any location).
2. `evil-want-keybinding nil` set before anything loads evil.
3. =config/= added to =load-path=; =lunaris.el= loaded (the whole backend).
4. =use-package= configured: `use-package-always-defer t` (doom-style lazy),
   `use-package-ensure-function` no-op (nix builds every package; never touch
   package.el / network).
5. Every `*-autoloads.el` on =load-path= loaded — the nix wrapper puts package
   dirs on =load-path= but never registers autoloads; without this step
   autoload-only entry points (e.g. `doom-themes-org-config`) are void.
6. =manifest.el= loaded — `(lunaris! ...)` records enabled modules for
   `modulep!`.
7. =config/= loads synchronously (stage 1: identity + keys + dashboard).
8. =lunaris-stage-2= walks =framework/= in the background (4 files per idle
   tick), loading each enabled group dir: the `<group>.el` file always, plus
   every `<module>.el` whose `(modulep! :<group> <module>)` is t. Modules are
   byte-compiled into =~/.cache/lunatix-emacs/lisp= on first run.
9. Doom-style defaults: no tabs, truncate, line numbers, no menu/tool/scroll
   bars, frame title = current buffer name.

=early-init.el=: `package-enable-at-startup nil`, `package-quickstart nil`.

* Own backend — lunaris.el

The whole backend in one file, clean config-side API only. Four parts:

** leaf

Own leaf-style package-declaration macro, recreated rather than importing
=conao3/leaf=. Thin wrapper over =use-package=; same keyword names so decls
read like leaf:

#+begin_src emacs-lisp
(leaf corfu
  :ensure t
  :demand t
  :config ...)
#+end_src

Supported keywords (pass through to =use-package=): =:ensure=, =:defer=,
=:demand=, =:hook=, =:bind=, =:config=, =:init=, =:custom=, =:after=,
=:commands=, =:when=, =:mode=. ~190 decls across =modules/= use it.

** Doom compat

The doom-compat layer uses the =luna-= prefix (unified naming); the old
=doom-= names remain as aliases for ported code. Macros:

| macro           | port of             | notes                                    |
|-----------------+---------------------+------------------------------------------|
| =after!=        | =after!=            | runtime =eval-after-load= (compiler-safe against self-feature cycles) |
| =map!=          | =map!=              | → =general-def=, per-state, error-swallowing |
| =cmd! / cmds! / cmd!!= | same        | interactive lambdas                       |
| =defadvice! =   | =defadvice! =       | → =defun= + =advice-add=                 |
| =modulep!=      | =modulep! =         | consults the =lunaris!= manifest         |
| =setq-hook! / add-hook! / remove-hook! = | same | hooks                          |
| =leaf=          | (own)               | declaration DSL                          |

Manifest =manifest.el= = `(lunaris! ...)` is the single source of truth for
`modulep!`.

Helpers (own implementations, =luna-= prefix): =luna-leader-key=,
=luna-localleader-key=, =luna-project-root=, =luna-call-process=,
=luna-region-active-p=, =luna-point-in-comment-p=, =luna-temp-buffer-p=,
=luna-fallback-buffer=, profile-dir functions, no-op hook variables
(=luna-escape-hook=, etc).

* Modules — framework/<group>/<module>.el

Layout mirrors doom's =modules/<group>/<module>/= as one file per module:
=framework/<group>/<module>.el=, plus a =framework/<group>/<group>.el= group
file with shared helpers. `lunaris-stage-2` loads each enabled group's group
file first, then every module file gated by `(modulep! :<group> <module>)`
(i.e. declared in =manifest.el=). Deleting a file or removing it from
=manifest.el= disables the module. Your personal config (always loaded, stage
1) lives in =config/=.

| dir        | doom group  | module files                                              |
|------------+-------------+-----------------------------------------------------------|
| =completion/| :completion | corfu, vertico                                            |
| =ui/       | :ui         | deft, doom, dashboard, hl-todo, indent-guides, ligatures, modeline, ophints, popup, smooth-scroll, unicode, vc-gutter, window-select, workspaces |
| =editor/   | :editor     | format, whitespace, snippets, fold, parinfer, file-templates |
| =emacs/    | :emacs      | electric, dired, ibuffer, eww, tramp, vc                  |
| =term/     | :term       | eshell, vterm                                             |
| =checkers/ | :checkers   | (off — no :checkers group in manifest)                   |
| =tools/    | :tools      | biblio, docker, editorconfig, eval, lookup, lsp, magit, pass, pdf, tree-sitter, upload |
| =lang/     | :lang       | agda, cc, common-lisp, data, emacs-lisp, go, java, javascript, latex, lean, lua, markdown, nix, org, php, python, qt, ruby, rust, sh, web |
| =email/    | :email      | wanderlust                                              |
| =app/      | :app        | calendar, irc, rss                                       |
| =config/   | :config     | default                                                  |

Stage-1 (always, in =config/=): =evil-config.el=, =general-config.el= (leader
definer =lunatix-leader=), =keybindings-config.el= (full doom `<leader>` tree +
localleader), =theme-config.el= (doom-monokai-octagon, JetBrainsMono 18 medium,
doom-modeline), =which-key-config.el=, =personal.el=, =org-extra.el=,
=denote-config.el=, =lang-extra.el=, =mistty-config.el=, =dirvish-config.el=,
=editor-extra.el=, =splash-config.el=.

** Manifest — manifest.el

`(lunaris! :completion (vertico +icons) (corfu +orderless) ...)` — your doom!
block, single source of truth. Feeds `modulep!` and the stage-2 loader;
submodules listed are the enabled set.

** Health check — `lunaris-doctor`

Doom-doctor-style per-module health check (`M-x lunaris-doctor` or batch).
Each group dir may ship a `doctor.el` (loaded only by the doctor, never by
stage-2) whose forms gate on `(modulep! ...)` and report via `ok!` / `warn!` /
`error!` — e.g. missing executables (lsp servers, compilers), unavailable
libs. Reports group by module; `lunaris-doctor-count` returns tallies for
tests. `test.sh` requires ≥1 `ok!`.

** Keybindings — keybindings-config.el

Unified structure, four consistent surfaces:

| surface | prefix          | role                            |
|---------+-----------------+---------------------------------|
| leader  | =SPC=           | actions (b buffer, f file, ...) |
| localleader | =SPC m=     | current major mode              |
| bracket | =[= =]=        | navigation: prev/next           |
| goto    | =g=, =M-g=      | jump (evil + xref)              |

Leader prefixes: =SPC := (M-x), =SPC b= buffer, =SPC c= code, =SPC e= denote,
=SPC f= file, =SPC g= git, =SPC h= help, =SPC i= insert, =SPC n= notes,
=SPC o= open, =SPC p= project, =SPC q= quit, =SPC r= remote, =SPC s= search,
=SPC t= toggle, =SPC T= workspaces, =SPC v= term, =SPC w= window
(=evil-window-map=).

Bracket navigation (doom convention): =[ b= / =] b= prev/next buffer,
=B= other-window, =f= prev/next file (recentf), =d= prev/next error,
=D= flycheck prev/next, =h= diff-hl prev/next hunk, =s= evil search prev/next,
=w= prev/next window.

Minibuffer: =ESC= aborts in one press, =C-s= consult-history, smart =C-a/C-e=.

* Nix integration

=modules/lunix/emacs/emacs.nix=:
- =emacs-overlay= input; overlay provides =emacsWithPackagesFromUsePackage=.
- Package single-source: nix reads =init.el= + all =config/**/*.el= and
  =framework/**/*.el= (recursive glob via `lib.filesystem.listFilesRecursive`,
  concatenated via =writeText=), parses `:ensure` decls, builds the package
  set. No second package list.
- =extraEmacsPackages=: eglot, treesit grammars, EAF composite (shared from
  =_eaf/apps.nix=).
- =services.emacs.package= is the result; =nix run .#emacs= / =.#doomacs=.
- Home packages include LSP servers, compilers, and =nerd-fonts.jetbrains-mono=.

Bootstrap cost: `use-package-ensure-function` no-op + nix-built packages means
zero network at runtime.

* Build / test

#+begin_src bash
  nix build .#emacs
  EMACS="$(nix build .#emacs --print-out-paths)/bin/emacs" ./test.sh
#+end_src

=test.sh= =emacs --batch= loads =init.el= with =debug-on-error t= and asserts 34
invariants: evil, leader tree, theme, modeline, which-key, dashboard,
completion stack, magit, lsp, smartparens, editorconfig, vterm, wanderlust,
elfeed, circe, persp, ultra-scroll, embark, menu/tool/scroll bars off, and
`lunaris-doctor` reporting ≥1 ok.

* Deviations from doom

| doom                       | lunatix                              |
|----------------------------+--------------------------------------|
| doom-popup                 | popper (side windows)                |
| doom workspaces core       | persp-mode                           |
| straight.el                | nix packages                         |
| doom core helpers          | lunaris.el ports                |
| rotate-text                | dropped (github-only, no nixpkgs)    |
| lean                       | dropped (no nixpkgs lean-mode)       |
| literate config            | n/a — config is plain elisp          |
